# Reproducing the airline analysis

Start with [REPORT.md](REPORT.md). The [workbook](analysis_workbook.xlsx) contains the supporting tables, and the [chart PDF](analysis_charts.pdf) contains ten figures. Each chart is also saved as PNG and SVG in `charts/`.

The original input files remain in the parent folder. Analysis assumptions were recorded in [ASSUMPTIONS.md](ASSUMPTIONS.md) before the relevant transformations. Exact source fingerprints, row counts, duplicate effects, and cost/revenue totals are in `preparation_audit.json`.

From the repository root, use Python 3.10 or newer:

```sh
python3 -m pip install -r analysis/requirements.txt
python3 analysis/prepare.py
python3 analysis/costs_gates.py
python3 analysis/routes.py
python3 analysis/commercial.py
python3 analysis/network.py
python3 analysis/present.py
```

Only `present.py` needs the third-party libraries. The numerical preparation and analyses use Python's standard library, SQLite, and integer cents. `prepare.py` writes a temporary database and publishes it only after all integrity assertions pass. It preserves source row numbers and writes every removed duplicate ID to a separate audit table. Do not reorder `transactions.csv` independently of its date decision log.

`airline_analysis.sqlite` contains normalized transactions, costs, gates, indexes, and a cost-events view. It is a derived analysis artifact, not a new authoritative source. Regenerate it from the CSVs and decision log; the scripts do not change source files.

The `tables/` CSVs contain the full numeric results. Commercial table columns ending in `_cents` are exact cents; the Excel workbook converts these to dollars and renames them accordingly. Other monetary CSV columns generally use dollar amounts with two decimals. The workbook's index lists each source CSV and its corresponding tab.

The main report and route/cost narrative files include reviewed interpretation of this dataset. If the sources change, rerun the scripts and review these narratives before relying on them; they are not automatically rewritten by every analysis script. Commercial findings are generated by `commercial.py`.

Validation includes exact calendar-year revenue reconciliation to the previous reports minus duplicates, route/month-to-network reconciliation, cost event completeness, duplicate-field agreement, physical-gate allocation reconciliation, and booking denominator checks. Additional independent subagent checks confirmed the totals and date rules.
